# Reactorcide web UI

A single-page application made with Zest web components
(`@catalystcommunity/*`), TypeScript and Vite. It has no application
framework. Do not add one. The Go binary embeds the build.

- `src/api/transport/` is a copy of `catalystcommunity/csilgen`'s
  `transports/typescript/src/`. Do not edit it here. Copy it again when the
  csilgen transport changes.
- `src/api/csilapi/` is generated by `scripts/generate-csil-ui.sh` from
  `coordinator_api/csil/reactorcide-ui.csil`. Do not edit it.

Build with `./tools build-ui` from the repository root. The build writes into
`webapp/internal/embedui/dist/` for `go:embed`. Test with `./tools test-ui`
(`npm test` here).

## How the UI is made

| Part | File | What it does |
| --- | --- | --- |
| Element base | `src/ui/element.ts` | `RcElement`: a Zest `BaseComponent` in the light DOM. |
| Page base | `src/app/page.ts` | `RcPage`, and `PAGES`: the lazy page modules. |
| DOM helpers | `src/ui/dom.ts` | `h()`, `s()` (SVG), `setText`, `setAttr`, `show`, `syncKeyed`. |
| Controls | `src/ui/controls.ts` | Makers for Zest controls, and `confirmAction`. |
| App store | `src/ui/store.ts` | One Zest `BasicDataService`. |
| Shared data | `src/store/` | Reference-counted, live resources (`useResource`). |
| Page data | `src/ui/load.ts` | `Loader`: a keyed load that one page owns. |
| Routes | `src/ui/router.ts` | Zest `SimpleRouter`, `resolveRoute`, `href`, `navigate`, `setQuery`. |
| Shell | `src/App.ts` | Header, navigation, and the routed page. |

### Elements

Each part of the UI that has a lifetime is an element that extends
`RcElement`:

- `build()` makes the elements ONE time, at the first connect.
- `connected()` gets what one connection holds: `useResource(this, ...)`,
  `this.own(...)`, `this.listen(...)`. The disconnect releases all of it.
- `render()` changes only the parts that changed. It runs after each
  connect, after each change of a collection in `static watches`, and after
  each `invalidate()`. It runs often, so keep it cheap.

Do not make a control again when its data changes. Make it in `build()`, then
change its text, attributes and properties in `render()`. A browser closes an
open list, loses typed text and resets a scroll position when an element is
replaced. Use `syncKeyed` for rows, so a row that stays keeps its element.
`ResourceView` (`src/components/States.ts`) builds its content one time and
calls `update(data)` for each refresh.

Do not give an element a member with the name of an `HTMLElement` member
(`title`, `remove`, `hidden`, `render` with other arguments).

After an `await`, call `this.isActive()` before you change the element.
`Loader` drops a response that is older than the newest request.

### Pages

A page extends `RcPage`, defines its tag, and exports it as `tag`. The shell
keeps the page element while `acceptRoute` is true. By default this is the
same page with the same id. Thus a query change (a filter) updates the page in
place. A page that reads the route reads `this.route()`. Its resource builders
read the route too, and `handle.sync()` in `render()` follows a change.

Org-management pages extend `ManagedOrgPage`
(`src/components/ManagedOrg.ts`). It shows the loading, refusal and no-org
states, and calls `buildBody()` one time and `renderBody()` while the page is
open.

Links use app paths through `href('/jobs/x')`. The shell routes each click on
a link under `/app/` in the page, except the server paths `/app/auth`,
`/app/rpc` and `/app/ws`.

### Controls

Use the Zest controls: `push-button`, `text-field`, `text-area`,
`check-box`, `combo-box`, `list-box`. Make them with the makers in
`src/ui/controls.ts`. `confirmAction()` replaces `window.confirm`.

- A control sends `input` and `change`, and both bubble. A listener on a
  wrapper must check `event.target === event.currentTarget`.
- A change from code sends no event.
- Put a control in a `Field` (`src/components/Field.ts`). The field draws the
  label, the required or optional marker, the hint, the tooltip and the error.
  The control gets the label as its `aria-label`.
- Set `options` before `value` on a combo box. `setOptions()` changes the
  options only when they differ, so an open list stays open.
- After a successful submit, clear a required field with `clearField()`.
  Otherwise the field shows "Please fill out this field" at once.
- A link that looks like a button is `<a class="btn">`.

### CSS

- `src/styles/layers.css` sets the layer order `page, zest`. Element rules
  (`h1`, `a`, `:focus-visible`) are in `@layer page`, so they do not change
  the inside of a light DOM control. Class rules have no layer.
- `[hidden]` always hides. A class rule that sets `display` does not show a
  hidden element.
- The Zest tokens come from the palette in `src/styles/tokens.css`. Set
  global `--zest-color-*` tokens there. Do not set a family or widget token
  to `var(...)` on `:root`.
- Do not give an application class the `zest-` prefix.
- `vite.config.ts` sets `build.cssTarget` so that `light-dark()` stays.

### Tests

- The tests use happy-dom. jsdom cannot read the Zest CSS (`@layer`).
- `src/test/mount.ts` has `mount`, `unmount`, `settle` (wait for renders) and
  `testHost` (an element for a helper test).
- happy-dom connects no custom element to its form. A `push-button
  type=submit` does not submit there: call the handler, or submit the form
  with `form.requestSubmit()` after you check the button.
- Do not import a module that imports the API client from
  `vitest.setup.ts`. The real client then loads before `vi.mock` applies.
